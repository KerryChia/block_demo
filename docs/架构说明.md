# 架构说明

```
┌───────────────────────── 浏览器（手机/PC，零构建单页） ─────────────────────────┐
│  入口（选人/起名） → 战斗屏（对话 + 双钱包 + 技能卡） → 侧栏（提示/链/榜/成就） │
└──────────────────────────────────┬───────────────────────────────────────────┘
                                   │ fetch /api/*
┌──────────────────────────────────▼───────────────────────────────────────────┐
│ FastAPI (server/main.py)                                                     │
│  ├─ /api/start → Engine.start_session                                        │
│  ├─ /api/chat  → Engine.chat                                                 │
│  │      1. 组装 system prompt = 人设(agents.py) + 实时链上状态                │
│  │      2. llm.chat() → OpenAI 兼容网关（失败整轮回滚，不消耗轮数）           │
│  │      3. 解析 <action>{"type":"transfer"|"balance",...}</action>            │
│  │      4. 执行：钱包扣减 → SQLite 落账 → Blockchain.add_tx → 回执注入历史   │
│  │      5. 成就检测（金丝雀/速攻/收割/技术统计）→ 事件流返回前端              │
│  ├─ /api/chain  → 区块浏览器（懒出块 + 整链重算校验）                         │
│  └─ /api/leaderboard → 每人每关最高局 Σ + 成就分                              │
└──────────────┬──────────────────────────────┬───────────────────────────────┘
               ▼                              ▼
     SQLite data/game.db              Blockchain data/chain.db
     sessions/messages/transfers/     SHA-256 PoW（前导 00）
     achievements                     内存池 → 3 笔或 60s 出块
```

## 关键设计决策

**防御写在提示词，不写死在代码。** 服务端只做幂等性校验（余额、金额、轮数上限），"信不信你"完全由 Agent 的系统提示词决定。这保证了：① 任何话术理论上都可能生效（涌现性 = 游戏性）；② 调难度 = 改 `agents.py` 文案，无需动代码逻辑。

**转账协议用标签而非 function calling。** `<action>` 标签在任何 OpenAI 兼容后端上行为一致（不依赖各家 function calling 质量），且"诱导 Agent 直接输出标签"本身就是攻击面的一部分。服务端解析失败会以链上回执形式反馈给 Agent 自我纠正。

**每关一个可发现的漏洞。** 难度递进不是"更严的过滤"，而是"更窄的信任锚"：
- Lv1 信任「身份声明」→ 冒充即破
- Lv2 只信任「[SERVER] 文本格式」→ 伪造格式即破（间接注入）
- Lv3 什么都不信，但制度上必须留两个口子（教学演示豁免 / 多签通知转发）→ 利用"规则例外"攻破

实测提醒：模型推理能力越强，Lv2/Lv3 的"世界观合理化"越重要（提示词里给了"实验室 IM 会把服务器通知转进聊天"的制度解释），否则模型会自行识破设计好的漏洞。

**LLM 失败即回滚。** 先组装上下文调用 LLM，成功后才落任何状态——网关抖动不烧玩家轮数。

**一条链，所有玩家共享。** 全活动共用一条人大链：得手即上链、创世块刻实验室标语、浏览器可整链校验——这同时是讲座环节"区块链不可篡改"的活教材。

## 线程模型

FastAPI 同步端点跑在线程池；`Engine._db_lock`（RLock）串行化 SQLite 访问，会话级 `threading.Lock` 保证同一局回合串行。活动规模（几十并发、每回合一次 LLM 调用）下瓶颈在上游网关而非本服务。
